# 프로젝트 실행 계획표

갱신일: 2026-10-23 · 계획 v3.2 · 코드 준비와 학습 완료를 구분한다.

## 목표와 실험 범위

**지식 증류가 작은 모델의 화질을 높이는지, 사진별 모델 선택이 화질을 비슷하게 유지하면서 전체 처리시간을 줄이는지 검증한다.**

- Mini 36 / Max 180 / Max+ 937개 파라미터. Max+는 프로젝트의 원본 해상도 보정망 추가 구성이며 전체를 처음부터 함께 학습한다.
- 기본 교사: 일반 학습 Max+. 외부 교사는 우리 학습 분할로 준비하고 검증 품질을 확인한 뒤 선정한다.
- 학습 구성: Mini·Max 각각 GT / BaseKD / StrongKD, Max+는 GT / StrongKD, 총 8개. 교사 학습·설정 탐색·반복 시드는 별도다.
- 학생의 GT와 KD는 동일한 `initial.pt` 및 같은 학습 예산으로 비교한다. 교사는 고정한다.
- 선택기는 밝기 등 입력 상태를 이용한 **규칙 기반**으로 진행한다. MLP는 확장 과제, Oracle는 제외한다.
- 결론은 품질 변화·CPU 전체 처리시간·메모리·학습 비용 및 실패 사례로 낸다. 개선을 미리 가정하지 않는다.

## 현재 실행 조건

| 항목 | 적용값 |
|---|---|
| 데이터 | LOL-v2-real, train 620 / validation 69 / test 100 |
| 장면 그룹 | 학습 227 / 검증 29, 분할 간 장면 중복 방지 |
| 학습 입력 | random 180×180 crop. 같은 seed·epoch·이미지는 같은 위치 |
| 검증 입력 | 69쌍 전체, 원본 해상도 600×400 |
| 공통 시작 설정 | seed 42, 120 epoch, batch 40, Adam lr 0.01, 40 epoch마다 ×0.1, FP32 |
| 학습 환경 | 사용 가능한 Colab GPU. GPU 종류·패키지 버전·실제 소요시간 기록 |
| 실행 코드 | 세 노트북의 CODE_REF는 분할 실행을 지원하는 같은 코드 커밋에 고정. 현재 main과는 역할이 다름 |
| 실험 이름 | `gt_random_v1`. 이전 `gt_v1` center 결과는 예비 실험으로 보존 |
| 저장·재개 | 기본 EPOCHS_PER_SESSION=120으로 남은 학습 끝까지 실행. 매 epoch Drive에 initial / best / last·직전 백업·로그·진행 상황 저장, 마지막 저장 epoch부터 재개 |
| 기준 모델 | 이번 Max-GT의 검증 69쌍 결과. 기존 LOL-v1 점수와 직접 비교하지 않음 |
| 최종 시간 측정 | 목표 Apple M5(10코어) CPU, 1스레드, FP32, batch 1, 600×400, warm-up 10 / 측정 100 |

120 epoch·batch 40은 공통 시작값이다. 실행 점검에서 변경이 필요하면 세 모델에 동일하게 적용하고 새 실험으로 구분한다. GPU 배정이나 학습 완료 시간은 보장하지 않는다.

## 작업 순서·담당·완료 기준

달력 날짜는 팀이 확정한다. 아래는 선행 조건에 따른 실행 순서이며 각 행을 완료했다는 뜻이 아니다.

| 순서 | 작업 | 담당 | 시작 조건 | 완료 기준·산출물 | 현재 상태 |
|---|---|---|---|---|---|
| 0 | 기준·실행 파일 확인 | A·D, 팀장 | 최신 GitHub 문서 확인 | 고정 manifest, 공통 설정, 모델별 노트북·결과 경로 | 코드·문서 준비 완료 |
| 1 | GPU 짧은 실행 점검 | 모델별 실행 담당, D 취합·B 시간 확인 | Drive 데이터·GPU 확보 | 각 모델 2배치 학습 + 검증 69장, 메모리·시간·저장 확인 | 실행 결과 미확인 |
| 2 | Mini·Max·Max+ 일반 학습 | 모델별 실행 담당, D 취합 | 해당 모델 점검 통과, 공통 설정 확인 | 모델별 initial.pt / best.pt / last.pt / log.csv / run.json / summary.json | 실행·완료 미확인 |
| 3 | 검증 품질·입력 상태 분석 | A·C | 해당 모델의 best checkpoint와 이미지별 JSON | 검증 평균, 밝기·품질 관계, 사진별 모델 차이, 사례 비교 | 학습 결과 대기 |
| 4 | CPU 비용 측정 | B | 모델·측정 규약 확보 | 목표 M5에서 시간·메모리 비교. 학습 전 구조 측정이면 별도 표시 | 목표 장치 정식 결과 미확인 |
| 5 | 기본 교사 증류 | D | Max+-GT best.pt 및 각 학생 GT initial.pt 확보 | Mini←Max+, Max←Max+의 같은 초기값·학습량 비교, β 기록 | 증류 노트북 준비, Max+-GT 대기 |
| 6 | 외부 교사 준비·증류 | 팀장·D, 담당 추가 지정 | 자원·후보 검증 | 교사 품질과 StrongKD 3종 결과, 교사 학습 비용 | Retinexformer 선정, 교사 학습·증류 노트북 준비 ([2단계 안내](stage2.md)) |
| 7 | 크기별 모델 선발·선택 기준 | A·C·D, 팀장 통합 | 비교 가능한 학습 결과 | Mini* / Max* / Max+*, 검증으로 정한 규칙·임계값 | `eval_checkpoint.py`·`selector.py` 준비, 결과 대기 |
| 8 | 설정 고정·최종 시험·시제품 | 전원 | 모델·규칙·평가 기준 고정 | 시험 100쌍 품질, 선택 비용 포함 시간·메모리, 실패 사례, 로컬 데모 | 예정 |

일반 학습 3개는 서로 독립적이다. 자원이 부족하면 순차 실행해도 된다. A·C는 완료된 모델부터 분석하고 B는 별도 목표 CPU에서 측정할 수 있다. 기본 교사 증류는 Max+-GT가 준비된 뒤 진행한다. 8개 학습 구성과 주요 결과 3시드 반복은 전체 계획에 남기되, 실제 반복 대상·계산 예산은 별도 고정한다.

## 중간발표와 역할별 전달

- **팀장:** 모델별 실행 담당 배정, 일정·범위 결정, 완료/미완료 결과 구분, PPT·시연 통합.
- **A:** 이미 고정된 데이터·평가 규약 확인. `best_validation_per_image.json`과 summary에서 검증 평균·이미지별 표 작성.
- **B:** 실제 Colab 학습 시간 지원, M5 CPU 성능 측정. 다른 서버의 수치를 M5 결과로 보고하지 않음.
- **C:** 검증 69장의 입력 밝기와 이미지별 결과 연결, Mini·Max·Max+ 차이·실패 사례 분석. 시험셋으로 규칙을 정하지 않음.
- **D:** 일반 학습 결과 취합, 동일 초기값 관리, Max+-GT를 교사로 Mini 증류 우선 비교 및 Max 증류 연결.

학습·교사 준비가 미완료면 코드·실제 진행량·소요시간·남은 비교를 제시한다. 부족한 비교로 증류 효과나 모델 선택 이득을 주장하지 않는다. 상세 업무는 [역할 분담](team_roles.md)을 따른다.

## 완료된 것과 아직 확인하지 않은 것

**완료:** 데이터 분할·평가 코드, 모델/증류/재개 코드, 초기값 공정성 수정, random·매 epoch 저장·선택적 분할 실행과 새 커밋에 고정한 노트북 3개, GitHub 업로드, 로컬 테스트 43개 통과(2026-10-23).

**미확인:** 실제 Colab GPU 점검·정식 학습 완료, 외부 교사 확정, 증류 개선량, 규칙 선택기의 실익, 목표 M5의 정식 비교 결과. CPU 테스트 통과는 GPU 학습 검증을 대신하지 않는다.

## 지킬 조건·남은 결정

- 검증 69쌍(29개 장면)을 checkpoint·β·교사·모델·임계값 선택에 함께 쓰므로 탐색 범위를 제한하고 한계를 보고한다.
- 시험 100쌍은 모델·방법·규칙을 고정한 다음 평가한다.
- 외부 교사, β, 선택 특징·임계값, 품질 허용 저하량, 실패 기준, 반복 시드·담당별 마감은 아직 미정이다.
- 옛 Drive 노트북 사본은 자동 갱신되지 않는다. [최신 실행 링크](../colab/README.md)에서 다시 열고 `학습 crop: random 180`을 확인한다.
- 분할 실행은 총 120 epoch와 학습률 일정을 바꾸지 않는다. 기본 구간 길이는 120으로 남은 학습을 진행하며 짧은 점검에만 5~10을 사용한다. 이번 학습 코드 변경에 맞춰 CODE_REF도 갱신한다.
