# 실행 기준과 이전 설계의 차이

2026-10-23. 아직 학습 결과로 검증된 결론이 아니라 이번 비교 실험의 실행 기준이다.

| 항목 | 현재 기준 | 이유·해석 범위 |
|---|---|---|
| 선택기 | 밝기 등 입력 상태를 이용한 규칙 기반 선택. 구체적 특징·임계값은 검증으로 선택 | 이번 핵심 범위를 단순하게 유지. MLP는 필수가 아니며 추가 시 데이터 분리와 복원 모델 재학습 필요성을 검토 |
| 데이터 | 기존 장면 단위 train 620 / validation 69 / test 100 유지 | 별도 라우터 학습 분할을 추가하지 않음. 검증 69쌍(29개 장면)을 여러 설정 선택에 사용하는 한계를 기록하고 탐색 범위를 제한 |
| 학습 입력 | 세 모델 모두 random crop 180×180 | 같은 중앙 영역만 반복하는 대신 서로 다른 위치를 학습. 효과 향상을 미리 단정하지 않음. 같은 seed·epoch·이미지는 같은 위치를 사용 |
| 검증 입력 | 원본 해상도 전체 이미지, 검증 69쌍 | crop 결과만으로 화질을 평가하지 않으며 시험셋으로 설계하지 않음 |
| 실험 경로 | `gt_random_v1` | `gt_v1`의 center 결과는 예비 실험으로 보존. 새 실험은 처음부터 학습하며 center checkpoint를 이어 쓰지 않음 |
| 학습 예산 | seed 42 / 120 epoch / batch 40으로 시작 | 짧은 실행 점검으로 자원 요구량 확인. 변경 시 세 모델에 동일 적용하고 새 실험으로 구분 |
| Max+ 구조 | Max + 3×3 conv(6→13) + ReLU + 1×1 conv(13→3), 총 937개 파라미터 | 이전 약 950개/두 residual block 설계를 단순한 원본 해상도 보정망으로 구체화한 구현 초안. 마지막 층을 0으로 초기화해 처음에는 Max와 같은 출력 |
| Max+ 학습 | Max 본체와 보정망을 처음부터 함께 학습 | 본체 동결 방식과 구분. 전체 모델이 과제에 맞게 학습되도록 하며 일반 학습·증류에서 학습 가능한 부분을 동일하게 유지 |
| 증류 출발점 | 일반 학습과 동일한 초기 가중치에서 동일 학습 예산으로 시작 | 학습된 checkpoint에서 추가 학습하는 이전 안 대신 증류 손실의 효과를 같은 출발점·학습량에서 비교. 학생 initial.pt를 보관하고 사용 |
| 기본 교사 | random 조건에서 일반 학습한 Max+의 best.pt | 속도 추측이 아니라 계획된 비교 조건에 따른 선택. 완료 후 교사를 고정하고 학생만 업데이트 |
| Oracle | 제외 유지 | 기존 사용자 결정과 현행 발표 계획을 따름. 계산 가능 여부와 필수 실험 포함 여부는 별개 |
| 시간 측정 | 같은 목표 M5 CPU에서 model / end_to_end 측정 | 다른 서버의 시간은 참고치. Colab 학습 시간·GPU 종류는 별도 기록 |

## 고정 커밋 갱신 절차

1. 공통 설정·생성기·문서를 수정하고 커밋한다.
2. `scripts/package_colab.py --github-ref <새 코드 커밋의 전체 SHA> --output colab`으로 세 노트북을 생성한다.
3. 노트북의 CODE_REF, EXPERIMENT, 해당 커밋의 crop 설정을 대조한다.
4. 노트북을 추가 커밋하고 두 커밋을 푸시한다. main의 변경만으로 과거 노트북 사본은 갱신되지 않는다.
5. 각 담당자는 최신 노트북을 열어 짧은 실행 점검부터 수행한다. 이 문서 작성 과정에서 Colab GPU 학습을 실행한 것은 아니다.
